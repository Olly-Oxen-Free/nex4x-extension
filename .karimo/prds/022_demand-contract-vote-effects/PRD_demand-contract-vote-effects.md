# PRD: Demand, Contract, and Coalition Vote Effects

**Slug:** demand-contract-vote-effects
**Created:** 2026-05-31
**Severity:** P1
**Source:** 2026-05-31 nex4x flaw audit

## Vision

Three core diplomatic subsystems — demands, contracts, and coalition votes — move from
stub/debug-only state to full gameplay participation. AI factions issue demands driven by the
existing `PRESS_GRIEVANCE` goal path; accepted demands produce real in-world effects (all
four implemented types plus a `FORCE_NEUTRALITY` addition). Contracts complete with a real
payoff (relationship-influence transfer, not literal faction credits — see API Constraint
below). Coalition votes are proposed from decision triggers, cast by all members, and
resolved on schedule with quorum enforced. The back-compat `resolve(blocLeaderId)` bypass
is retired.

## API Constraint: Contract Payoff Modeling

Starsector's `FactionAPI` holds no credit treasury. The `CargoAPI.getCredits()` path is
player-fleet-only; AI factions cannot transfer literal credits to each other. Therefore
contract "payment" is modeled as:

1. **Relationship/influence transfer** — winner's influence ledger gains the computed
   second-price `pay` converted at a configurable rate (`contractInfluenceRate`, default
   1 credit = 0.1 influence points), paid by the issuer faction.
2. **Covert-action dispatch** — `complete()` registers the contracted covert action with
   Nex's `CovertOpsManager` (same path as PRD-013 agent actions) using the winning bidder
   faction's first available agent. If no agent is available the action is logged as
   unexecuted and the influence is still transferred (issuer still paid for the outcome
   commitment).
3. **Player-as-bidder exception** — if `winnerFactionId` is the player faction,
   `GlobalSector().getPlayerFleet().getCargo().getCredits().add(pay)` is called instead
   (literal credit delivery IS valid for the player fleet).

This is a deliberate design choice, not a limitation to paper over. It is documented as
`// DESIGN: AI factions cannot hold credits; contract payoff uses influence transfer.`
in the implementation.

## Why Now

- `DemandManager.issue` / `accept` / `reject` have zero callers outside debug commands
  (grep confirmed: only `advanceDay()` is wired in `Nex4xManager`). The `PRESS_GRIEVANCE`
  goal type is generated by `GoalGenerator` and scored/ranked by `StrategicGoalManager`
  but `DiplomaticExecutor.executeDiplomaticAction` has no case for it — the action is
  silently dropped every tick.
- `ContractAuctionManager.complete()` (line 71) flips status and logs only — no credit
  transfer, no covert action, no relationship change. `post()`/`bid()`/`complete()` have
  no callers outside `ContractAuctionManager` itself and the `advanceDay()` loop.
- `CoalitionGovernance.proposeVote()`, `getBlocLeader()`, `getPendingVotes()` have no
  callers outside `CoalitionGovernance.java` itself. The `advanceDay()` loop (line 97)
  prunes already-resolved votes but never resolves pending ones — votes accumulate and
  never fire. The back-compat `resolve(String)` overload (line 78) passes `memberCount=0`,
  bypassing the quorum guard at line 61.
- All three issues are observable in a fresh campaign: no AI demand appears in any intel
  log; no contract completes with a visible result; COALITION agreements govern nothing.
- The `votes/` package (`VoteProposal`, `VoteOutcome`) is fully dead — zero callers
  across `src/`. Removal is flagged Out-of-scope here; tracked as PRD-025.

## Success Criteria

1. An AI faction with an active `PRESS_GRIEVANCE` goal and sufficient pressure/influence
   issues a demand within 30 in-game days; the demand appears in `DemandManager.getAll()`.
2. A pending demand is accepted or rejected by the target AI faction within the 14-day
   window; `applyDemandEffect` fires the correct side-effect.
3. `ContractAuctionManager.complete(c, true)` transfers influence to the winner faction
   (or credits to the player fleet) and dispatches the contracted covert action.
4. `CoalitionGovernance.advanceDay()` resolves pending votes when `DEFAULT_TIMEOUT_DAYS`
   elapses; quorum is enforced using real member count; passed votes trigger their effects.
5. `resolve(String)` (memberCount=0 overload) is removed or redirected to quorum path.
6. Build green: `./build.sh` exits 0.
7. Debug smoke: `Nex4xDebugCommand.auditDemands()` shows an issued + resolved demand;
   `auditContracts()` shows a completed contract with influence delta; `auditVotes()` shows
   a resolved vote with quorum data.

## Scope

**In:**
- `DiplomaticExecutor.executeDiplomaticAction` — add `PRESS_GRIEVANCE` / `EXPLOIT_WEAKNESS`
  case that calls `DemandManager.issue()`.
- `DiplomaticExecutor.advanceDay` — add AI accept/reject logic for demands directed at its
  faction (reads `DemandManager.getPending()`).
- `DemandManager.applyDemandEffect` default branch — add `FORCE_NEUTRALITY` type; log
  remaining unimplemented types as `[Nex4x] WARN: unhandled demand type`.
- `ContractAuctionManager.complete()` — apply influence transfer + covert-action dispatch;
  handle player-faction credit exception.
- `CoalitionGovernance.advanceDay()` — resolve pending votes on timeout using correct
  member count; apply vote effects (ADD_MEMBER/KICK_MEMBER/DISSOLVE/DECLARE_WAR/MAKE_PEACE).
- `CoalitionGovernance.proposeVote()` — wire a call site from `AgreementManager` on
  member-join or from `DiplomaticExecutor` on COALITION-tier goal events.
- `CoalitionVote.resolve(String)` back-compat overload — remove or throw
  `UnsupportedOperationException` directing callers to the `(String, int)` form.
- `Nex4xDebugCommand` — add `auditDemands()`, `auditContracts()`, `auditVotes()` runcodes.
- `Demand.DemandType` — add `FORCE_NEUTRALITY` enum value.

**Out:**
- `votes/VoteProposal.java` and `votes/VoteOutcome.java` removal (PRD-025).
- Player-facing demand UI (separate negotiation flow — PRD-023 candidate).
- Contract bidding from player fleet UI (deferred).
- `applyDemandEffect` for demand types beyond the five defined here (deferred per type).
- Any changes to `src/nex4x/ui/` beyond adding debug runcode entries.

## Risks

- **Over-issuing demands**: PRESS_GRIEVANCE goal fires daily per faction. Mitigation: add a
  `demand_cooldown_days` guard in `DiplomaticExecutor` (configurable, default 30 days per
  demander-target pair). Check `DemandManager.getPending(factionId)` before issuing.
- **CovertOpsManager API drift**: Nex's `CovertOpsManager.queueAction()` signature may
  differ across Nex versions. Mitigation: wrap in try/catch; fall back to influence-only
  payoff if Nex agent dispatch fails.
- **Coalition member count mismatch**: `getCoalitionMembers()` in `AgreementManager` must
  be the canonical source for vote resolution denominator. Confirm the method counts
  transitively (A-B + B-C = three-member coalition).
- **Quorum deadlock on small coalitions**: two-member coalition requires 1/2 participation;
  both must vote or timeout auto-resolves FAILED_QUORUM. This is correct per spec.
- **Save compatibility**: new `FORCE_NEUTRALITY` enum value must maintain existing ordinals;
  add at end of `DemandType` to avoid deserialization breakage.

## Acceptance

- `./build.sh` exits 0 with no compile errors.
- `runcode nex4x.debug.Nex4xDebugCommand.auditDemands()`: output shows at least one issued
  + resolved demand with correct status and non-null effect logged.
- `runcode nex4x.debug.Nex4xDebugCommand.auditContracts()`: output shows a completed
  contract, winner faction id, influence delta or credit delta, and covert-action result
  (dispatched / no-agent / player-credit).
- `runcode nex4x.debug.Nex4xDebugCommand.auditVotes()`: output shows at least one resolved
  vote with member count > 0, quorum fraction met or explicitly FAILED_QUORUM.
